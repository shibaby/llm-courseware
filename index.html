第 1 章 · 大模型是什么

约 6 分钟

它本质是一台「文字接龙大师」

先忘掉“神经网络”“人工智能”这些吓人的词。大模型做的事只有一件：看着前面的文字，猜下一个词。训练时，它把海量书籍、网页、代码读了个遍；使用时，它把你说的每句话当成“接龙的开头”，一个词一个词往下接。

训练 = 海量阅读使用 = 预测下一个词输出 = 一个词一个词往外蹦
今天→ 天气→ 真→ 好→ ……

所以它不是在“查资料”，而是在“接话”。这也解释了它为什么有时特别会说，有时却一本正经地胡说八道。

超级大脑，但有三个「不能」

不能 01

不知道新事

训练数据有时间截止点，之后发生的事它天然不知道。想让它知道，就得把资料递给它——这就是后面 RAG 要干的事。

不能 02

不记你

它只有一个临时工作台叫上下文。新开一个对话，工作台就清空了；聊得越久，台面越满。

不能 03

动不了手

它只能输出文字，不能真的订机票、查天气、改文件。要动手，就得给它配工具（Tool）。

副作用

会自信地胡说 = 幻觉

因为它只负责“接得像”，不负责“接得对”。遇到不确定的地方，它也可能用非常肯定的语气编一个答案。重要结论务必自己核对，或让它给出处。

把人话记住：它是一颗超级大脑，但被关在聊天框里。后面所有技术，都是在给它补东西。

亲手接一次龙

点「开始接龙」，看它如何只做一件事：每一步，从候选里挑一个最可能的词。

输入（Prompt）

他每天早晨

注意：它不会“想清楚整句话”再开口，而是每 500 毫秒猜一个词，猜完再猜下一个。

记住这个 大模型是一颗超级大脑，但被关在聊天框里。它不知道新事、不记你、动不了手，还会自信地胡说。后面所有技术，都在给它补手、记忆、参考书和员工手册。

接下来先逛一张“概念全家桶”地图，把 Token、Prompt、RAG、MCP、Skills、Agent 这些词一次认全；然后再逐个拆开。

第 3 章 · Agent 智能体

约 8 分钟

Agent = 给大脑配上手脚和循环

普通 Chatbot 像坐在窗口后的问答机：你问一句，它答一句。Agent 像被派出去办事的实习生：你只给目标，它自己想下一步、动手做、看结果，没办完就继续转。

Chatbot

问答机

你问：“北京周五天气？”它答：“晴，26℃。”答完就结束，不会顺手替你订票。

Agent

办事员

你说：“帮我订周五去北京的票。”它会查车次、比较、下单、确认，直到出票。

差别

目标 vs 问题

Chatbot 接收“问题”，Agent 接收“目标”。差别不只在模型多聪明，更在外面那圈脚手架。

Agent = 模型（大脑）+ 工具（手脚）+ 循环（想 → 做 → 看）

先记住这个公式。下一节把“循环”画出来看。

它的工作节奏：想 → 做 → 看 → 再想

这不是一次性问答，而是一个不停转的圈。点一点四个节点，看看每一格在干什么。

想（Reason）+ 做（Act）= ReAct。名字很唬人，直觉就是：边想边做，边做边看。

亲手推进一次订票任务

你只给它一个目标。每点一次「走一步」，看它如何想一步、做一步、看一眼。

目标帮我订一张周五去北京的高铁票
想 做 看
✅ 出票成功——从头到尾，只给了一个目标

注意：它不是在“一次回答里想完所有事”，而是走一步、看一步——这正是 Agent 和普通问答的分水岭。

最大的误区

常见误解

“换个更强的模型，就成 Agent 了吧？”

不是。Agent = 模型 + 脚手架。模型负责想，脚手架负责给它工具、记忆、循环和护栏。同一个模型，接上这些能订票；拔掉这些，它仍然只是个聊天框。

模型 + 工具 + 循环 + 规则 = Agent

工具

让“想”变成“做”：查资料、调用接口、写文件。

记忆

记住目标、中间结果和已经试过的路，别每轮都失忆。

护栏

哪些事能自己做、哪些要先问人、什么时候必须停。

记住这个 Agent 不是“更聪明的模型”，而是模型 + 工具 + 循环：大脑负责想，手脚负责做，眼睛负责看，没办完就继续转。

Agent 要动手，就得有统一的“工具插座”。下一章看看 MCP 怎么把 M×N 根线，收成一根 USB-C。

第 4 章 · MCP

约 8 分钟

每个 AI 应用，都要重新接一遍工具

ChatGPT 要连邮箱、Claude 要连日历、Cursor 要连 GitHub……如果每对组合都单独写一套接口，就是 M×N 条定制线。MCP 要做的，是把它们收成 M+N。

应用方

M 个应用

ChatGPT、Claude、Copilot、Cursor……每家都想连上同一批工具。

工具方

N 个工具

邮箱、日历、数据库、GitHub、文件——每家都有自己的接口。

结果

M×N 套胶水

每加一个应用或工具，都要重写、重测、重新维护一遍。

M 个应用 × N 个工具=M×N 条定制线→ 装上 MCP →M+N 条标准线

先别记缩写：把它想成 USB-C——插座统一了，谁都能插。

把乱麻，收成一个插座

左边 4 个 AI 应用，右边 5 个工具。没有标准时，它们两两对接；装上 MCP 后，所有线都插到同一个 hub。

现在：20 根定制线，每加一个工具就要再连一遍。装上 MCP：9 根标准线——4 进 + 5 出，也就是 M+N。

一次调用，经过谁？

MCP 不是一根魔法线，而是三段接力。你只需要认识三个角色。

HOST

你用的应用

ChatGPT、Claude、Cursor……它发起请求，也把结果呈现给你。

CLIENT

翻译官

把“查天气”翻译成 MCP 的标准请求，再把结果译回来。

SERVER

工具方

邮箱、数据库、GitHub 的适配器，真正执行动作并返回数据。

类比：Host 是顾客，Client 是前台，Server 是后厨。顾客不直接进厨房，前台负责把话传到。

几个值得记住的事实

这些时间点能帮你判断：MCP 已经不是“某个厂商的小工具”，而是行业共同维护的标准。

反面教材：实测 5 个服务器的工具定义就占约 5.5 万 token。所以“全装上”并不划算——这也是下一章 Skills 要解决的事。

MCP 不是模型

常见误解

“装了 MCP，AI 就更聪明了？”

不会。MCP 是接口标准，不生产智能，也不训练模型。就像 USB-C 不生产电器——它只负责让插头对得上。真正干活的，还是模型和工具。

记住这个 MCP = AI 世界的 USB-C。把 M×N 条定制线，收成 M+N 条标准线；Host → Client → Server，各司其职。

工具接上了，新的问题来了：工具一多，模型上下文会被“说明书”塞爆。下一章看 Skills 怎么做到“用时才展开”。
